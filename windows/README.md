# Jev 伴聊 Windows 预览版 0.4.1

本目录提供源码和第三方运行环境许可。构建命令见文末；下述安装器说明适用于从该源码编译得到的安装包。2026 年 10 月 21 日的本地验证通过了 39 项核心检查和 x64 交叉编译，窗口 OCR 仍待真机验收。

适用系统：Windows 10 2004（19041）及以上、Windows 11，**x64**。ARM64 和 32 位系统未提供原生包。

**这是实际编译生成的 Windows 安装程序，内含 .NET 运行环境，不需要另装 Python、Codex 或 .NET。0.4.0 的用户截图已确认界面能打开，但聊天控件定位失败。0.4.1 已完成交叉编译和 39 项核心检查，新加入的窗口画面识别仍待 Windows 真机验证。模型层沿用此前通过虚构对话请求与响应验证的实现。**

## 0.4.1：处理“聊天区未向只读接口提供内容”

旧版提示来自“找不到固定名称的聊天输入框”，不能据此证明微信没有提供任何界面内容。新版增加原始控件树和结构定位，并在定位失败时进入窗口画面识别。

1. 关闭旧版 Jev，运行新安装包更新；原有加密模型配置保留。
2. 在微信打开聊天，点击 Jev 的“读取微信”；也可直接点“窗口识别”。
3. 助手会临时隐藏自身，把微信切到前台并读取它当前可见的画面。首次在预览中**框选右侧消息区**，保留左右气泡，排除联系人列表、标题和输入框。
4. 点“记住区域并识别”。核对识别文字和“我 / 对方”，再点“逐条分析”。
5. 后续窗口尺寸和微信版本不变时可以复用选区，无需手动使用截图快捷键。窗口尺寸或版本变化会要求重选；调整侧栏、缩放或布局后，请主动到“连接设置 → 重选微信消息区域”。

窗口识别只在本机处理选区，图片不保存、不上传。它不会写入微信进程内存，不改签名或系统安全设置。需要 Windows 提供 OCR 语言；优先使用已安装的中文识别语言，否则使用系统可用的识别语言。

窗口被置顶窗口、弹窗遮挡或移出屏幕时会停止读取，避免把其他内容识别进聊天。请移开遮挡并保持微信可见，再次点击“窗口识别”。如果读取仍失败，到“连接设置 → 复制读取诊断”获取版本、控件数量、阶段和尺寸；诊断不包含消息、图片或密钥。

画面识别无法可靠取得联系人 ID，因此每次读取都清除旧分析和本次上传授权，重新核对后分析，**不自动跟随或自动调用模型**。只读控件模式的跟随功能仍保留。读取失败时，界面可保留上次内容供查看，但暂停分析，避免误把旧聊天当成这次结果。

## 安装与启动

1. 把 `JevCompanion-Setup-0.4.1-win-x64.exe` 发到目标 Windows 电脑，双击后点“安装并打开”。
2. 安装到当前用户的 `%LOCALAPPDATA%\Programs\JevCompanion`，创建桌面和开始菜单快捷方式。无需管理员权限。
3. 第一次进入“连接设置”，配置目标电脑能够访问的模型服务。
4. 可先选择“示例”再“逐条分析”，确认模型能实际返回结果，再使用聊天文字。

安装程序未签署商业代码签名证书，Windows 可能显示“未知发布者”或信誉提示。请核对文件来源及随包的 SHA-256；若系统策略阻止运行，请使用该电脑允许的安装流程，不要关闭防护。

更新前请关闭旧版 Jev 伴聊，重新运行安装包。可以通过 Windows“设置 → 应用 → 已安装的应用 → Jev 伴聊”卸载。卸载保留加密连接配置；如需清除，可以另行删除 `%LOCALAPPDATA%\JevCompanion\settings.json`。

## 模型到底用谁的账号？

**安装包不含开发电脑的 Jev、9Router 账号或密钥，不会自动连接那台 Mac。**

- **9Router：分析与回复**：填写服务地址、密钥和模型。分析与回复均由所选模型生成，卡片注明 `9Router · 模型名`。这里的概率是该模型的估计，不是 TypeSafe Jev 的判断结果。
- **TypeSafe Jev 判断 + 可选 9Router 回复**：填写自己的 TypeSafe API Key。判断直接发送到 `https://api.typesafe.ai/v1/systemone`；如同时配置回复模型，则由 9Router 生成当前最新对方消息的回复草稿。
- 界面采用苹果风格：蓝色（我）/ 浅灰（对方）气泡、白色分析卡及细进度条。该改版只改视觉，已通过交叉编译与 39 项核心检查，尚未在 Windows 真机上目视验收。
- 密钥使用 Windows DPAPI 按当前系统用户加密保存，界面中用密码框显示。

`http://127.0.0.1:20128/v1` 表示**运行客户端的那台 Windows**，前提是它已运行 9Router。要共用另一台电脑的模型服务，需先另行部署带身份验证的 HTTPS 入口，再填对应地址与凭证。本包没有部署或开放开发电脑的任何服务。不要直接将 Mac 的本机地址发给对方。

“刷新模型列表”只检查服务是否可达及模型目录。真正的调用是否成功，要以逐条分析结果为准。

## 微信 4.1.15.8 的使用入口

- **读取微信**：先尝试当前微信窗口的 UI Automation 元素；无法定位聊天区或超时后进入窗口画面识别。0.4.1 的新路径仍需真机验证。
- **窗口识别**：直接读取微信窗口画面，并识别你选中的消息区。首次框选，尺寸和版本匹配时可复用。
- **截图识别**：按 `Win + Shift + S` 框选微信右侧消息区，保留左右气泡，不包含联系人列表与输入框；回到助手点“截图识别”。使用 Windows 本机 OCR，不上传截图。系统需要可用的 OCR 语言组件；识别后请核对文字和发送方。
- **粘贴**：每行一条，写成 `我：……` 或 `对方：……`。没有前缀的消息标为未知。
- **示例**：内置虚构聊天。没有固定分析分数，必须调用真实模型后才显示灰色分析卡。

点击气泡上方的“我 / 对方 / 发送方待确认”可修正文字或发送方。手动修正会关闭自动跟随。

“逐条分析”只处理对方消息；每条只带截至该条的前文，不带后续消息。未知发送方需先确认。真实文字分析前会说明发送范围。失败会显示原因，可单独重试；“停止后续”保留已经完成的卡片，等待当前请求结束后停止下一条。

“跟随”仅在只读接口成功读取微信后可用。每 3 秒检查，自动分析至少间隔 15 秒，切换聊天时暂停。截图与粘贴不支持自动跟随。模型回复只提供复制按钮，由使用者核对后自行在微信发送。

## 当前限制

- 分析显示在独立 Jev 窗口中，没有嵌入或修改微信原窗口。
- 新版的安装更新、窗口切换与画面读取、选区复用、OCR 仍未完成 Windows 真机验收。
- UI Automation 发送方基于位置谨慎判断，长气泡等不确定情况标为未知；OCR 分行与发送方同样可能需要修正。
- 只读接口只覆盖当前已暴露的文字，不保证未加载历史、图片、语音或后台消息。
- 此 Windows 预览版不持久保存聊天与分析结果，关闭应用即清空；仅保存加密模型配置。尚未移植 macOS 的原文记忆库。
- 读取会话依赖界面标题，没有稳定微信账号 ID，不支持多个同时打开的微信主窗口。

## 源码与构建

`Core/` 是可跨平台测试的消息协议、连接校验、Jev 与 9Router 客户端；`App/` 是 Windows WPF 界面、DPAPI 配置、安装器与采集器；`Tests/` 包含不依赖微信或真实凭证的隔离检查。

需要 .NET SDK 10：

```powershell
dotnet run --project Tests/Jev.Tests.csproj -c Release
dotnet publish App/Jev.Windows.csproj -c Release -r win-x64 --self-contained true -o dist
Copy-Item dist/JevCompanion.exe dist/JevCompanion-Setup-0.4.1-win-x64.exe
```

同一个单文件程序通过安装包名称识别安装入口；安装后复制为 `JevCompanion.exe`，直接启动助手。`--install` 也能进入安装器。Windows 专用程序集可在 macOS 使用 `EnableWindowsTargeting` 交叉编译，但交叉编译不能替代 Windows 运行验证。

第三方运行环境的许可说明随源码和安装程序资源保存在 `Notices/` 中。
