# 实现设计

## 用户操作与数据流

```text
当前微信界面 / 用户粘贴 / 内置虚构示例
    ↓ 原文 + 发送者角色 + 会话域 + 内容指纹
SwiftUI 状态管理器
    ↓ 用户确认当前会话和服务范围
Python 后端
    ├─ 本地检索已保存的同会话原文
    ├─ TypeSafe / Jev：独立诉求判断、下一步动作、紧张程度
    └─ 9Router：基于原文、检索证据和判断生成两条回复草稿
    ↓ 核对快照仍然有效
浮窗展示概率、建议动作、原文和可复制草稿
```

## 技术取舍

界面与读取使用 SwiftUI / AppKit / Accessibility，避免引入大型桌面运行时。Python 后端只使用标准库，通过独立进程处理网络与 SQLite。没有监听 HTTP 端口、云中转服务或微信协议实现。

Jev 默认使用随源码提供的独立客户端，凭证来自环境变量或专用钥匙串，也可显式指定外部调用器；9Router 使用本机 Chat Completions 接口。模型选项来自实时列表，账户路由和原有模型配置不由本应用修改。

概率全部来自实际 Jev 响应。多个诉求采用独立 Noul 判断，可同时成立；动作采用含“不确定”的 Choice；紧张程度采用五档 Score 并换算到 0–10。它是沟通强度估计，不是客观危险评级。

## 状态与边界

- 来源、会话域、消息正文指纹、模型配置共同决定结果有效性。内容或来源变化会让在途旧结果失效。
- 分析前使用固定快照；微信分析结束时再次核对当前会话，避免把 A 的建议显示在 B 中。
- 不因读取时间变化重复请求；自动模式一次只处理一个请求，错误不触发无界重试。
- 云处理确认绑定当前范围；聊天正文不能扩大授权或成为工具指令。
- 消息源文件及界面中的文本按数据处理。不存在允许模型执行系统命令或发送微信消息的工具。
- 记忆默认关闭；开启后只写入原文和来源，不写入推断。会话名可能重复，持久记忆要求独立别名。
- 同一个原生进程既没有发消息接口，也没有对微信的鼠标键盘操作路径。

## 0.2 聊天流与逐条分析

同步视图使用对方白色、我方绿色气泡；Jev 灰卡绑定分析输入最后一条消息的 ID，不把后来发生的内容倒填成旧消息的判断。点击“分析到这里”截断当前片段到所选消息，既有同会话匹配历史仍可作为补充证据。

分析卡只在本次运行中缓存。真正尾部追加新消息时保留已有卡；前缀有修改、删除、重排，或会话、来源、配置改变时，清除失效结果。新消息不会自动获得虚构百分比。

## 0.2 真实读取故障定位

初版按深度优先遍历整个微信窗口，先进入左侧会话列表。真实故障计数为：423 个节点、130 个侧栏条目、4009 ms；达到 4 秒预算时尚未到达消息表和输入区。该故障不是微信没有文字，也不是 Jev 或 9Router 没有返回。

读取诊断仅记录阶段、数量、耗时、属性读取状态，不保存联系人名称、消息正文或时间文本。读取调度先定位窗口骨架，再读取当前消息区，侧栏的可见名称检查最后进行。

## 降级

无辅助功能权限：使用粘贴或内置示例。

Jev 失败：不生成概率，不用假数据填充。

9Router 失败：保留已经取得的 Jev 结果，明确显示模板草稿与错误原因。

历史为空：告知尚无匹配原文，提示确认具体所指，不编造昨天发生的事。

## 验证范围

隔离测试覆盖会话历史隔离、授权、示例内容校验、消息去重、模型数值解析、原文引用、超时/HTTP 错误、9Router 格式与认证，以及微信 3.8/4.x 界面结构夹具。

真实调用仅用虚构对话进行。端到端状态以交付时的 `../docs/VALIDATION.md` 为准；自动测试、模型调用、本机微信读取是三个独立的验证层次。
